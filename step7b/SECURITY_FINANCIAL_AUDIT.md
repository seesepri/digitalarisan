## Arsitektur data dan alur uang yang ditemukan

- Nominal disimpan sebagai PostgreSQL `BIGINT` dan Drizzle mengeluarkannya sebagai JavaScript `number`. Wallet memiliki available/locked/pending balances, non-negative checks dan unique wallet per user. Wallet transactions menyimpan saldo sebelum/sesudah, referensi, idempotency key unik, dan reversal link.
- `joinPeriod()` mengunci periode untuk mengurutkan pendaftaran/capacity, lalu wallet; membuat participant dan reservation, memindahkan available→locked, mencatat ledger dan memeriksa jumlah reservation. Pembatalan melakukan owner check, lock periode/participant/wallet/reservation, melepaskan reservation, mengembalikan saldo dan menulis ledger. Rujukan: [arisan service](src/server/services/arisan.ts#L28-L47), [pembatalan](src/server/services/arisan.ts#L179-L205), [schema wallet ledger](drizzle/0000_baseline.sql#L408-L430).
- Drawing/settlement berada di satu transaksi yang mengunci periode, memakai CSPRNG, memvalidasi otorisasi maker-checker untuk operasi manual, dan memperbarui pool, fee, payout, participant/reservation/ledger. Scheduler memiliki bearer secret, lease/retry dan idempotent drawing. Implementasi utama: [settlement](src/server/services/arisan.ts#L356-L395), [scheduler](src/app/api/v1/jobs/run/route.ts#L42-L74).
- Top-up membuat intent dahulu, lalu menghubungi adapter di luar transaksi DB; saldo hanya dikredit setelah signature/provider status diverifikasi. Webhook mengunci top-up, mengecek provider/amount/currency, menyimpan event unik dan ledger idempotent. Reconciliation memanggil status provider. Batas antara DB dan jaringan eksternal tetap perlu diuji pada timeout/crash.
- Withdrawal memerlukan KYC `VERIFIED`, row lock wallet, saldo dipindah available→pending, PII bank dienkripsi, risk flags dihitung. Approval dan eksekusi provider mensyaratkan checker berbeda dari approver; provider reference stabil/idempotent, status ambigu tetap `PROCESSING`, retry berbatas. Detail: [withdrawal creation](src/server/services/wallet.ts#L103-L163), [state machine](src/server/services/payout-withdrawal.ts#L32-L116), [provider execution](src/server/services/payout-withdrawal.ts#L175-L220).
- Ledger wallet dan financial accounts dilindungi trigger immutable; audit memiliki sequence/hash chain dan trigger insert. Reconciliation membandingkan wallet reservations/balances, continuity dan semantic ledger movement, orphan references, idempotency/provider duplicates, payout/fee totals. Baseline: [immutable ledger trigger](drizzle/0000_baseline.sql#L620-L640), [audit integrity trigger](drizzle/0000_baseline.sql#L665-L698), [reconciliation service](src/server/services/reconciliation.ts#L28-L100).
- **Risiko integritas yang masih perlu dibuktikan:** nominal `BIGINT` dipetakan menjadi `number` (IEEE-754). API membatasi satu permintaan sampai Rp50 juta, tetapi saldo kumulatif/database tidak dibatasi ke `Number.MAX_SAFE_INTEGER`. Kebijakan/constraint overflow harus diverifikasi sebelum saldo berpotensi mendekati $2^{53}$ rupiah; ini bukan reproduksi bug pada saldo normal.

## Temuan prioritas dan status

### Diperbaiki dan diverifikasi

1. **P1 — KYC self-approval administrator.** Sebelumnya route mengizinkan admin memverifikasi akun sendiri, sementara withdrawal hanya memeriksa KYC VERIFIED. Sekarang status VERIFIED untuk `id === admin.id` ditolak (`KYC_SELF_APPROVAL_BLOCKED`) dan regression test lulus. Rujukan: [KYC endpoint](src/app/api/v1/admin/users/%5Bid%5D/kyc/route.ts#L10-L19), [regression check](tests/financial-authorization-audit.test.ts#L61-L65).
2. **P1 — Checkout redirect Midtrans / adapter tidak dibatasi.** URL provider sebelumnya hanya diperiksa non-empty, sehingga response salah/terkompromi dapat mengarahkan user ke domain phishing dan custom Midtrans base URL dapat mengirim server key ke host lain. Sekarang checkout URL HTTPS; Midtrans redirect harus host Midtrans yang diizinkan; API base HTTPS/host sesuai mode dan `MIDTRANS_IS_PRODUCTION` wajib eksplisit. Regression test provider 10/10 pass. Rujukan: [validasi URL](src/server/services/payment-provider.ts#L47-L65), [Midtrans config](src/server/services/payment-provider.ts#L144-L162).
3. **P2 — Race duplicate privacy request / keputusan admin.** Check lalu insert sebelumnya tidak terserialisasi. Sekarang request pengguna mengunci row user sebelum check+insert dan rate-limit per-user; keputusan admin mengunci row request. Test privacy 19/19 pass. Rujukan: [user request](src/app/api/v1/privacy/requests/route.ts#L11-L25), [admin decision lock](src/app/api/v1/admin/privacy/requests/route.ts#L61-L91).
4. **P2 — Refresh reuse audit/revoke rollback.** Throw dari dalam callback transaksi Drizzle membatalkan revoke-family dan audit yang baru dibuat. Branch reuse kini mengembalikan sentinel, transaction commit dahulu, kemudian route mengirim 401. Regression test memastikan urutan ini. Rujukan: [reuse handling](src/app/api/v1/auth/refresh/route.ts#L36-L43), [401 setelah commit](src/app/api/v1/auth/refresh/route.ts#L75-L77). Ini tidak menyelesaikan false-positive race dua tab yang dijelaskan di bawah.
5. **P2 — Retention governance tidak terdokumentasi di workspace.** Ditambahkan [snapshot governance](PRIVACY_DATA_GOVERNANCE_V21.md) yang mendokumentasikan hanya perilaku terverifikasi dan secara eksplisit memisahkan unknown/legal policy dari fakta kode.
6. **P1 — Release migration gate menolak baseline yang aktif.** Verifier awal gagal: `drizzle/MIGRATION_CHECKSUMS.sha256` tidak ditemukan; checker juga mensyaratkan urutan mulai 0001 padahal journal dan folder aktif memakai `0000_baseline.sql`. Ditambahkan checksum, dukungan explicit baseline 0000 + migrasi berurutan, validasi path, duplicate rejection, cakupan checksum wajib untuk setiap SQL migration aktif, dan penyesuaian preflight. Verifier sekarang lulus, satu migration diperiksa. Rujukan: [verifier](scripts/deploy/verify-migrations.mjs#L8-L25), [preflight](scripts/dr/migration-preflight.sh#L8-L17), [manifest](drizzle/MIGRATION_CHECKSUMS.sha256).

### Masih terbuka / perlu tindakan sebelum production

1. **P1 — Upgrade/cutover DB existing belum terbukti.** Tree `drizzle/` aktif hanya memiliki baseline squashed; file migration 0001–0014 berada dalam direktori backup, bukan urutan migrasi aktif. Lolosnya verifier berarti checksum baseline konsisten, **bukan** bahwa baseline dapat dijalankan aman di database existing, bahwa journal production cocok, atau bahwa perubahan lama sudah ter-bootstrap. Wajib lakukan preflight/restore + migration rehearsal pada salinan database staging yang disposable, bandingkan catalog/schema/checksum dan migration journal; tentukan prosedur baseline adoption/upgrade/rollback. Jangan jalankan bootstrap pada production sebelum itu. Konfigurasi DB live NOT VERIFIED.
2. **P2 — Refresh dua request paralel dapat menyebabkan logout semua perangkat.** Dua tab mengirim refresh cookie yang sama; request pertama membuat session baru, request kedua melihat token lama revoked lalu mencabut semua session aktif, termasuk session baru. Reuse detection melindungi pencurian token tetapi rentan false-positive/DoS. Pertimbangkan single-flight refresh client, rotation-family/grace model dengan threat analysis, lalu uji concurrency tanpa mematikan reuse detection.
3. **P2 — Pemulihan password bergantung pada akses nomor/SIM.** Reset password sekarang menggunakan OTP Twilio pada Verify service terpisah dan mencabut semua sesi. Risiko SIM swap/perpindahan nomor tetap ada; reset bukan KYC/MFA dan tindakan finansial berisiko tinggi tetap memerlukan kontrol sendiri. Twilio credentials, service configuration/funding, SMS delivery, serta DB migration belum diverifikasi production. MFA, email verification dan ganti password saat sesi aktif belum ditemukan.
4. **P2 — Pembatasan rate belum seragam.** Beberapa tindakan privileged (mis. retry job manual, KYC/status sebelum perbaikan, admin arisan config) sebelumnya tanpa throttle; sebagian berisiko rendah kini dibatasi. `GET` reconciliation, consent, notifikasi-read dan join/cancel masih tanpa limit route-level. Tentukan kapasitas/abuse budget dan rate limit sesuai risiko, jangan hanya bergantung pada batas platform.
5. **P2 — Kegagalan database dan provider eksternal tidak diuji integratif.** Top-up/payout mengombinasikan transaksi DB dengan HTTP eksternal; titik crash setelah provider menerima permintaan, webhook berulang/out-of-order, dua worker, deadlock, recovery/reconcile dan key rotation perlu diuji terhadap PostgreSQL disposable serta fake/sandbox provider. Suite concurrency/crash-recovery tersedia tetapi sengaja tidak dijalankan karena database uji belum dipastikan.
6. **P2 — Provider generic mempercayai kontrak idempotensi provider.** API adapter mengirim `Idempotency-Key`, tetapi jaminan tepat-satu disbursement bergantung perilaku provider yang dikonfigurasi. Validasi endpoint/egress allow-list, TLS, idempotency retention upstream, timeout ambiguity dan status reconciliation harus disahkan pada kontrak/provider deployment aktual.
7. **P2 — Rate-limit IP memerlukan konfigurasi reverse-proxy yang benar.** Production menolak rate limit bila `TRUST_PROXY !== true`, namun saat true implementasi membaca `X-Forwarded-For` pertama. Pastikan hanya trusted ingress dapat mencapai app dan ingress menghapus/menimpa header client; jika tidak, IP spoofing dapat bypass throttling. Topologi/konfigurasi aktual NOT VERIFIED.
8. **P2 — Export data bisa tidak lengkap untuk akun besar.** JSON export memakai limit tetap 500 pada beberapa collection tanpa cursor/indikator truncation. Tambahkan export job/pagination dan manifest kelengkapan atau eksplisit tandai truncation; uji volume besar dan perlindungan download/cache.
9. **P2 — Uji schema/DB privileges dan audit immutability butuh live verification.** Trigger immutable/hash chain terdapat di baseline, tetapi pemilik tabel, grant, migration role terpisah, superuser bypass, restore integrity dan apakah runtime DB role dapat `ALTER/DISABLE TRIGGER` tidak diverifikasi. Next 16 menandai `middleware` deprecated. `.github/workflows` tidak ditemukan dan Git metadata tidak ada di workspace ini; CI release enforcement/tracked lockfile/secret scanning tidak dapat diverifikasi. ## Checklist OWASP Top 10 + financial abuse

- **Broken Access Control:** status sesi dicek di server; role `requireAdmin`/`requireSuperAdmin`; mutasi owner-scoped dan route finansial penting maker-checker. Tidak ditemukan route mengganti role; hak role di DB/operator belum diuji.
- **Cryptographic Failures:** scrypt password; token refresh acak disimpan hash; HMAC access claims; cookies HttpOnly/Secure production/SameSite=Lax; AES-GCM bank PII; webhook timing-safe signatures. Key storage/rotation/backup UNKNOWN; hash biasa consent evidence bukan tanda tangan/verifikasi legal.
- **Injection:** Drizzle parameter binding dan validasi utilitas terlihat; tidak ada string SQL concatenation yang ditemukan pada jalur finansial yang ditelaah. SQL raw template masih harus dijaga tetap parameterized.
- **Insecure Design:** ledger/reservation/idempotency/reconciliation baik; phone-based reset mencabut sesi dan tidak login otomatis; belum ada MFA/step-up, dan reset tetap rentan SIM swap; false-positive refresh race; risk thresholds default/env belum business-approved.
- **Security Misconfiguration:** response headers CSP/HSTS prod ada; middleware lama dan build workspace-root warnings; CORS/proxy/DB deployment config NOT VERIFIED.
- **Vulnerable Components:** production `npm audit` 0 high+; dependency lock version 3 ada; audit penuh dev dependency/CI pinned reproducibility tidak diverifikasi sebagai release pipeline.
- **Auth Failures:** throttling, hashed passwords, session server-state/rotation, Twilio Verify phone OTP, dan phone-based password reset ditemukan; MFA, change-password, email verification, session management UI, serta production Twilio delivery/configuration belum ada atau NOT VERIFIED.
- **Integrity/Logging:** audit hash chain dan append-only ledger; sensitive-key redaction; audit log response redacted. Operator DB/superuser tampering dan immutable retention proof belum diuji.
- **SSRF / outbound:** tidak ada user-controlled URL/fetch route ditemukan dalam audit terarah; provider base URL adalah konfigurasi env. Midtrans API URL sekarang allow-listed; generic provider egress allow-list tetap deployment control.
- **Abuse/resource exhaustion:** beberapa pagination caps, payload webhook 32 KB, provider timeout/circuit/backpressure dan rate buckets; upload/file API tidak ditemukan. Per-route throttling dan limits volume/retention perlu konsistensi.

## Kriteria penutupan

Jangan ubah temuan menjadi PASS hanya berdasarkan hasil source test. Sebelum go-live, jalankan penuh lint/type/build, security gate pada CI dengan Git checkout bersih, migration rehearsal pada clone/snapshot staging, integration/concurrency/crash recovery dan reconciliation terhadap DB disposable, Midtrans/payout sandbox end-to-end, secret/IAM review tanpa mencetak credential, serta restore/backup/retention drill. Simpan hasil run, versi aplikasi/schema, migration journal, provider event test, dan bukti approval maker-checker tanpa data pribadi/secret.
